# Commit Message Rule

## 기준

현재 git log는 대체로 `[type] 한국어 요약` 형식을 사용한다.

예시:

- `[feat] 주사위 굴리기, 점수판 초안 완성`
- `[fix] 점수, 턴을 서버에서 관리하도록 수정`
- `[style] 다이스 디자인 보완`

앞으로도 이 형식을 기본 규칙으로 사용한다.

## 형식

```txt
[type] 변경 내용을 한 문장으로 요약
```

## type

- `[feat]`: 사용자에게 보이는 기능 추가
- `[fix]`: 버그 수정, 잘못된 동작 수정
- `[refactor]`: 동작을 유지하면서 구조 개선
- `[style]`: UI 스타일, 포맷, 문구, 디자인 변경
- `[test]`: 테스트 추가 또는 테스트 구조 변경
- `[docs]`: 문서 추가 또는 수정
- `[chore]`: 설정, 패키지, 빌드/개발 도구 변경

## 작성 원칙

- 한국어로 짧고 구체적으로 쓴다.
- 한 커밋에는 하나의 주요 목적만 담는다.
- 여러 목적이 섞이면 커밋을 나눈다.
- 메시지는 "무엇을 바꿨는지"가 바로 보이게 쓴다.
- 불필요하게 긴 설명은 본문에 적고, 제목은 60자 안팎으로 유지한다.

## 이번 리팩터링 같은 경우

```txt
[refactor] 게임 상태 동기화 구조 정리, 품질 게이트 추가
```
